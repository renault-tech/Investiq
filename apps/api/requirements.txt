# Vercel's Python runtime reads this file directly (no pyproject.toml
# support) — kept in sync with the dependencies list in pyproject.toml,
# minus:
# - uvicorn: Vercel imports `app` directly (see api/index.py) and never
#   runs a uvicorn server process, so it's dead weight in the function
#   bundle (uvicorn[standard]'s httptools/uvloop/watchfiles/websockets
#   extras only matter for the Docker/local entrypoint).
# pypdf and fpdf2 ARE included below (PDF invoice upload and the monthly PDF
# report, respectively): both are pure Python with no native/binary chain —
# pypdf installs at ~4MB, fpdf2 at ~1MB — cheap enough to ship unconditionally.
# This used to run pdfplumber instead of pypdf for invoice parsing, which was
# excluded from this file for exactly the opposite reason: its fontTools +
# pypdfium2 chain alone is ~45MB, which pushed the Vercel function past the
# 225MB bundle cap and made PDF invoice upload production-only-in-Docker.
# pypdf gives up pdfplumber's table/layout reconstruction, but the extracted
# text goes straight into an LLM to pull out line items, so raw text is all
# this needs.

# Tetos de major version: sem eles, um build "frio" (sem lockfile — este
# requirements.txt não fixa patch/minor de propósito, ver comentário do
# topo do arquivo) resolve o que houver de mais novo no dia. Um pulo de
# major nessas duas SDKs (openai 1.x -> 3.x, google-genai 1.x -> 2.x)
# quase dobrou o peso de cada uma (openai: 11MB -> 6MB instalado,
# google-genai: 8.5MB -> 7MB) e sozinho foi o que estourou o limite de
# 225MB de função do Vercel num deploy sem nenhuma dependência nova —
# o código foi escrito e testado contra a API 1.x de ambas.
openai>=1.30.0,<2.0.0
# google-genai também engordou bastante dentro da própria 1.x (1.0.0 tem
# ~1.9MB instalado, 1.75.0 já tem ~7MB — o SDK foi ganhando módulos de
# API que este app não usa a cada patch). Mesmo com o teto de major acima
# (<2.0.0), o build ainda estourava por ~0.8MB; travar num ponto mais
# cedo da 1.x recupera ~4.5MB de sobra.
